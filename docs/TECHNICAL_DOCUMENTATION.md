# Technical documentation

## Objective and scope
Implement an end-to-end **demonstration** MLOps architecture with synchronous churn probability prediction, experiment tracking, simple drift monitoring, feedback collection, and retraining triggers.

## Architecture
See `../architecture.mmd` (Mermaid format). Dashboard and external clients call the FastAPI service. The service loads a serialized scikit-learn model. Training compares Logistic Regression and Random Forest and logs metrics and model artifacts to local MLflow runs. Incoming labeled feedback is stored as CSV. A scheduled or manual retraining job can merge feedback and the synthetic reference dataset and overwrite the active local model.

## Data contract
Input fields: `age`, `income`, `tenure`, `usage`, `support_tickets`. Label: `target` (0 or 1). Data generated by `src/data.py` is synthetic; labels are arbitrary simulation outputs, not empirically validated churn labels.

## Validation
Stratified 80/20 split, metrics: accuracy, F1, ROC-AUC. Winner selected by F1 on the held-out split; this also makes that split a selection set, not an untouched final test set. Use nested evaluation and business validation for real deployment.

## Drift
Population Stability Index (PSI) compares request feature distributions to training reference data; default alert threshold 0.2. Observations live only in API process memory. This is a feature drift signal, not ground-truth performance degradation detection. Small samples can be noisy.

## Retraining
`python -m src.retrain_job` checks `data/incoming/feedback.csv` for at least `MIN_NEW_ROWS` labeled rows. Manual `/admin/retrain` does the same. The new candidate replaces the model locally without a formal promotion gate. For production, retraining must run on persistent infrastructure and include validation, registry promotion, rollback, and approval rules.

## Security and limitations
The admin endpoint is unauthenticated and must never be publicly exposed as-is. CSV append is suitable only for local single-instance demos. Avoid sending real personal data. Cloud deployment, CI-to-runtime release, central model registry, persistent monitoring, and rollback require external accounts and configuration.

## Demonstration checklist
1. `docker compose up --build`
2. Open `/docs` and `GET /health`
3. Use dashboard prediction form
4. Refresh drift chart after generating requests
5. Run `mlflow ui --backend-store-uri ./mlruns --port 5000` for local experiments (run training on host to populate host-side mlruns)
6. Review GitHub Actions CI, CD and scheduled retraining YAML
7. Explain production gaps transparently.
